**The pattern worth repeating: build the gate first, then sweep the
configuration matrix through it.** That closed two of three VSM "shipped but
never looked at" gaps and found four real bugs — a premise the docs stated
confidently was false and had been for months
([[virtual-shadow-maps]], [[skeletal-animation-initiative]]).

**And profile before designing** — three of my own or the docs' premises were
falsified by measurement: [[gltf-import-cost]], [[texture-upload-batching]],
[[ibl-precompute-cost]]. Startup is ~10x faster end to end on Sponza across
seven measured PRs (texture memory 366→91 MiB, glTF import ~1035→~15 ms,
renderer init on Sponza ~1270→~127 ms). Frame time at defaults, **15.24 ms**,
was untouched by all of it; per [[mainhdrpass-attribution]] the frame path's
"find useless work" line is closed.

**Pixel gates are scene-specific here:** the default scene is bit-reproducible
(0/3686400), Sponza is not (one pixel at (816,850), delta 37, flipping between
runs of the same binary). Match the scene to the gate, or use a non-pixel
equivalence check like the LOD chain log diff.
