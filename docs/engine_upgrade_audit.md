# Engine Upgrade Audit

This document started as the Phase 0 repository audit and was refreshed during
Phase 7 to describe the current portfolio-ready renderer state. It is a status
document, not a roadmap for adding new rendering features.

## Current Repository Shape

- `src/core/` owns application startup, SDL3 window creation, event polling, PNG
  screenshot writing, logging, and the main loop.
- `src/rhi/` owns Vulkan instance/device/swapchain/resource wrappers,
  Synchronization2 helpers, debug labels, timestamp queries, VMA-backed buffers
  and images, texture upload, shadow maps, environment maps, and BRDF LUTs.
- `src/renderer/` owns frame orchestration, render objects, draw-item
  construction, material state, bindless texture heap, runtime settings, GPU
  profiler integration, scene JSON save/load, and Render Graph metadata.
- `src/assets/` owns the path-based `AssetManager` for material JSON assets and
  texture path metadata. Runtime Vulkan images still live in renderer/RHI code.
- `src/ui/` owns Dear ImGui integration through `ImGuiLayer`.
- `src/shaders/` contains all GLSL sources compiled by CMake with `glslc`.
- `assets/` contains the committed test glTF, fallback textures, portfolio
  material JSON files, and intentionally small runtime assets.
- `config/` contains the tracked runtime settings example. User-local
  `config/runtime_settings.json` is generated by the UI and ignored by git.
- `screenshots/` contains finalized portfolio captures. Phase 7 does not modify
  those files.

## Build And Runtime Entry Points

The root `CMakeLists.txt` defines the C++20 `VulkanEngine` executable and the
`VulkanEngineShaders` target. It first tries installed packages, then can fetch
SDL3, GLM, Volk, and Vulkan Memory Allocator from pinned tags when
`VULKAN_ENGINE_FETCH_DEPS=ON`. The Vulkan SDK is required for headers and
`glslc`.

CMake embeds these source/build paths into the executable:

- `VULKAN_ENGINE_SHADER_DIR`
- `VULKAN_ENGINE_ASSET_DIR`
- `VULKAN_ENGINE_CONFIG_DIR`

`src/main.cpp` constructs `ve::Application`, which creates `Window` and
`Renderer`, forwards SDL events, and calls `Renderer::drawFrame()` until exit.

## Implemented Renderer Scope

The current project is a C++20 Vulkan 1.3 real-time renderer prototype. It is
not a full game engine. Implemented systems include:

- Vulkan 1.3 device setup with Dynamic Rendering, Synchronization2, Volk, VMA,
  SDL3, optional validation, debug labels, and RAII-style resource wrappers.
- Static mesh rendering for built-in geometry and static glTF triangle meshes.
- glTF material factor and base-color/normal/metallic-roughness texture loading.
- PBR shading with Cook-Torrance GGX direct lighting, tangent-space normal
  maps, Kulla-Conty-style multi-scattering compensation, IBL, GGX prefiltered
  specular environment maps, and a split-sum BRDF LUT.
- PCF-filtered cascaded shadow maps with basic texel snapping, optional debug
  tinting, GPU shadow-caster culling, and indirect shadow drawing when
  supported.
- HDR scene color, mip-chain bloom by default, legacy blur fallback, GPU
  exposure state, Reinhard/ACES tone mapping, and an optional TAA foundation.
- GPU frustum culling, optional conservative previous-frame Hi-Z occlusion
  culling, indirect drawing, and culling debug counters.
- Render Graph 2.0 metadata with logical handles, pass read/write declarations,
  conservative image transitions, selected declared buffer barriers, liveness
  metadata, and ImGui visualization.
- Per-pass GPU timestamp profiling with frame-latency readback and ImGui timing
  history.
- Editable runtime scene workflow for object names, visibility, transforms,
  camera/light settings, JSON scene save/load, and material asset path metadata.
- JSON material asset loading/saving for scalar PBR fields and path metadata.
- Overlay-free portfolio screenshot capture from the tonemapped swapchain image
  before ImGui.

## Frame Flow

The current frame flow is:

1. Handle minimized/resized state and read completed-frame exposure, culling,
   timestamp, and screenshot readbacks after the frame-slot fence is signaled.
2. Acquire a swapchain image, reset the command buffer, build ImGui data, update
   render objects, build draw items, update culling inputs, and upload
   `ObjectFrameData`.
3. Begin Render Graph metadata, import swapchain/depth/shadow/TAA/depth-pyramid
   resources, and declare transient scene/bloom resources.
4. Render cascaded shadow maps, optionally dispatching GPU shadow culling per
   cascade.
5. Dispatch main GPU frustum culling and optional conservative Hi-Z occlusion
   against the previous completed depth pyramid.
6. Render skybox and mesh draws into `SceneColorHDR`.
7. Build the max-depth Hi-Z pyramid from stored main-pass depth.
8. Optionally run `TAAResolvePass` into the current HDR history image.
9. Run bloom, luminance, histogram exposure, GPU exposure reduction, and final
   composite.
10. Copy a portfolio screenshot only when explicitly requested.
11. Draw ImGui, transition the swapchain image to present, submit with
   `vkQueueSubmit2`, and present.

## Current Render Graph

`renderer::RenderGraph` is still a compact renderer-owned graph, not a full
production scheduler. It currently declares:

- `CSMShadowPass`
- `MainGpuCullingPass`
- `MainHDRPass`
- `DepthPyramidPass`
- optional `TAAResolvePass`
- legacy bloom extract/blur passes
- mip-chain bloom downsample/upsample passes
- `LuminancePass`
- `HistogramExposurePass`
- `CompositePass`
- `ImGuiPass`

It tracks logical texture and buffer handles, imported/transient resource
metadata, declared access, conservative image transitions, selected declared
buffer pass-to-pass barriers, side effects, pass liveness, and debug UI rows.
Physical resource allocation remains in `Renderer`, and shadow-culling,
intra-pass reset/copy, host-readback, and screenshot-copy barriers remain manual
in `Renderer.cpp`.

## Scene, Mesh, Material, And Assets

Current renderer-side scene data is deliberately small:

- `Camera` stores position, target, up vector, FOV, and near/far planes.
- `Transform` stores position/rotation/scale or a matrix override.
- `RenderObject` stores a stable runtime/editor ID, debug ID, name, visibility,
  mesh/material pointers, optional glTF material table, source type, transform,
  and portfolio/debug flags.
- `Mesh` owns GPU-local vertex/index buffers, submesh primitive ranges, local
  bounds, and debug names.
- `Material` stores runtime texture pointers, descriptor state, bindless
  indices, PBR factors, alpha metadata, source asset path, source type, and
  fallback flags.
- `AssetManager` provides stable path-derived material/texture handles and
  material JSON load/save, but it does not own Vulkan GPU resources.

Scene JSON is intentionally narrow. It restores matching runtime objects,
camera/light settings, object names, visibility, transforms, and simple material
asset assignments when the material already exists in the runtime scene. It does
not create objects, rebuild mesh assets, rebuild glTF material tables, or act as
a full editor scene format.

## Debug UI And Portfolio Workflow

Dear ImGui exposes renderer controls and inspection panels for:

- runtime settings save/load/reset
- tone mapping, exposure, bloom, and TAA controls
- CSM controls
- GPU culling and occlusion settings/counters
- portfolio capture mode and screenshot status
- Render Graph pass/resource tables
- GPU profiler timing history
- scene hierarchy editing and camera/light controls
- material scalar editing, save, and reload
- texture, render-target, TAA history, depth-pyramid, and CSM previews

Portfolio capture mode is a runtime preset for presentation screenshots. It is
not an offline renderer, and F12 should only be used when intentionally updating
screenshots.

## Accurate Limitations

- No full game engine, physics, gameplay scripting, full ECS, production editor,
  asset browser, material graph, or texture import pipeline.
- Render Graph 2.0 is not an async compute scheduler, multi-queue scheduler,
  memory aliasing allocator, or production transient-resource system.
- Occlusion culling is optional, conservative, AABB based, and uses the previous
  completed frame's depth pyramid.
- TAA is a foundation pass only. It has no motion vectors, depth reprojection,
  temporal upscaling, reactive masks, or broad camera-cut detection.
- Reflections are environment-based IBL only. There is no SSR, ray tracing,
  planar reflection, local reflection probe, or glass transmission/refraction.
- glTF support is static and narrow: no animation, skinning, morph targets,
  cameras, lights, alpha blend/mask pipelines, or occlusion maps. Emissive
  factor + emissive maps are supported.
- Upload paths still use simple queue-idle one-time command buffers for
  initialization and are not a runtime streaming system.
- GPU profiler timestamps are useful pass-duration estimates, not CPU/GPU
  calibrated timeline events.
- Portfolio screenshots use the current swapchain resolution rather than a
  separate high-resolution offline render path.

## Phase 7 Result

Phase 7 is documentation, release polish, and user-facing missing-file handling.
It does not add new rendering features or refactor unrelated renderer systems.
